# D-DERIVED-1: This repository publishes its own derived data

**Status:** Ratified
**Date:** 2026-09-04
**Decided by:** Jed Reinitz
**Prompted by:** jayostis/spec#56, which proposes a committed, freshness-gated `derived/`
directory here, lifted from the pipeline jayostis/sdk-typescript#89 built downstream. The
maintainer's call the epic reserved was "whether it is worth doing at all." This is that call.

---

## The decision

**GO.** This repository will publish, beside its authored Turtle, a generated `derived/`
layer that every consumer reads instead of parsing Turtle and re-deriving the rules itself:

- expanded JSON-LD graphs of every **stable** ontology and shapes file, one node per subject,
  `rdfs:comment` kept, `rdf:List` as `@list`, blank nodes under canonical labels;
- `manifest.json` stating, per vocabulary, directory, prefix, namespace, status, version,
  and the source and derived paths; drafts named as drafts; the aggregate context given a
  stated role;
- `record-types.json`, one row per class carrying `cascade:RecordClass` in a stable
  vocabulary, with its published JSON names, deprecation, unique successor, and shapes.

Generated by a Python script beside the existing gates, **committed** (a git pin can only
read what is committed, and the diff of the derived tables is the review of a vocabulary PR),
**byte-deterministic** under any hash seed, **freshness-gated in CI** (regenerate, compare,
fail naming stale, missing or orphaned files), round-trip-checked against the source graphs,
and uploaded as a release asset on every `vocab/*` tag for consumers whose CI has no checkout.

## Why

Every consumer today re-derives the same facts from the same Turtle with its own parser and
its own copy of the population rule, and no two copies agree by construction. The downstream
prototype proved the pipeline works; it also proved the cost of running it downstream: every
consumer carries a Turtle parser at build time, with licensing, drift guards and a
share-of-terms heuristic to guess which context belongs to which namespace. Those are facts
this repository knows and should state once.

This is also the "one authoritative copy" rule applied to derivation: the authored Turtle stays
the only thing anyone edits, and everything a consumer needs is generated from it here, where
the generator is reviewed with the source it reads.

## Conditions

1. **`cascade:RecordClass` lands upstream first**, through the vocabulary checklist with a
   fresh version number. `record-types.json` is keyed on it. Phase 1 (graphs and manifest)
   does not depend on it and may proceed in parallel.
2. **Python, with the pinned `rdflib`.** The downstream Node prototype is evidence, not the
   code to import. This repository does not gain a second toolchain for this.
3. **The generator emits the JSON itself.** `Graph.serialize(format="json-ld")` orders nodes by
   hash seed and is never the emitter; the determinism control runs the generator under two
   seeds and requires identical bytes.
4. **Nothing under `derived/` is edited by hand, and nothing generated lives anywhere else.**
5. **The context agreement check and the "can the contexts be generated" measurement
   (the epic's Phases 3 and 5) wait for the context-format decision, D-CONTEXT-1
   (`2026-09-04-context-format.md`), ratified the same day.** They are in scope; they
   are sequenced behind it.
6. **Drafts are named in the manifest and not otherwise published.** A `v1-draft` vocabulary
   enters `derived/` when it graduates, by the same generator, with no code change.
7. **SHACL-derived flat tables (required fields, value sets) are out.** Publishing them would
   encode one consumer's reading of SHACL as spec. A consumer evaluates the shapes graph.

## Consequences

- The phases are filed as issues in this organisation's repositories, not on a fork, and the
  consumer migrations (Phase 4) are filed in the consumer repositories and tracked from here.
- `scripts/check-downstream-versions.sh`, `VOCAB_VERSIONS` and the frozen test specimens are
  untouched. The manifest agrees with `VOCAB_VERSIONS`; a separate check says so.
- The vocabulary checklist's per-consumer steps become "re-pin, copy `derived/`, regenerate
  types." See D-LAYERS-1.
